# 烧饼论坛热榜 2.1.0

**[安装 / 更新脚本](https://sbhot.voee.de/shaobing-hot.user.js)** · [服务首页](https://sbhot.voee.de/) · [采集状态](https://sbhot.voee.de/api/status)

烧饼论坛侧栏热榜，官方榜单优先，只有实时和周榜使用后台采集。保留 NodeSeek 热榜插件的前十条、展开收起与切换交互。

## 安装与使用

安装 Tampermonkey，打开上面的安装链接，确认安装后刷新 https://sb.sb/。面板位于用户卡片下方，支持明暗主题、浏览/回复双榜和四个时间范围：

| 选项 | 统计范围 |
|---|---|
| 实时 | 最近1小时内观测到的新增浏览/回复 |
| 24小时 | 官方24小时榜，保持官方顺序与口径 |
| 周榜 | 滚动7天增量 |
| 30天榜 | 官方30天榜，保持官方顺序与口径 |

默认展示10条；官方榜展开官方提供的完整列表，自建榜最多100条。官方日/月榜立即可用，不需要等待采集；自建周榜需要从基线完成后积累7天，积累期间明确标注实际统计时长。

## 数据来源与减负

- **24小时、30天榜**：后台每15分钟各读取一个官方页面，统一缓存浏览/回复双榜，所有用户共享。保留官方顺序、数量和统计说明；当前浏览榜按周期内发布主题的累计浏览量排序，回复榜按周期新增回复排序。鼠标悬停可查看官方口径。
- **实时、周榜**：共用一份持久化快照数据，活跃主题每5分钟扫描，全站列表每轮完成后1小时再扫描。全量扫描频率相较v2.0减半；不活跃主题的浏览变化最多要等待全量扫描才被观察到。
- **存储**：只需覆盖7天窗口，增量记录保留9天（原32天），扫描记录保留10天；已有数据库和基线保留，不重建。
- **失败处理**：官方刷新失败时保留上次官方缓存并提示延迟，绝不悄悄用自建数据冒充官方榜。首次尚未获取官方数据时明确报错。

后台请求间隔至少2秒，失败退避，不访问主题详情刷浏览量。自建榜是公开计数的快照差分，增量记入被观察到的时间，窗口边界有采样误差；不等同于论坛内部事件日志。私有、删除或不可见内容不能完整观测。首次读取旧主题只建立基线，不把历史累计值当成当前热度。

官方榜时间标记显示“同步”，自建榜显示“采集”；脚本每分钟读取服务缓存，不会因用户增加而重复抓官方页面。

## 后台接口

只读 HTTPS GET：

- `/healthz`：服务和数据库可读性，`ready` 表示首次全量扫描完成。
- `/api/status`：主题数、最近扫描、分页进度及错误。
- `/api/rankings/realtime`、`daily`、`weekly`、`monthly`：四周期 JSON，包含浏览/回复双榜、采集时间、窗口积累状态。

`warming_up` 代表窗口不足或采集覆盖不完整（仅自建榜）；`coverage_gap` 标记窗口内完整扫描的长间断；`status.stale` 代表完整扫描超过3小时没有成功或尚未建立基线。`observed_seconds` 是基线完成后的已积累时长，不会伪装成完整7天。

## 开发与验证

Node.js 22+、Python 3.11+：

```sh
npm ci
pip install -r backend/requirements.txt
npm test
npm run check
python -m unittest discover -s tests -p test_backend.py -v
npx playwright install chromium
node tests/browser.cjs
```

主题列表样本来自2026-11-02公开页面。`rankings.json` 是用主题样本构造的客户端测试数据，不是生产增量统计。测试覆盖基线、增量、重复采集、新帖补记、滚动窗口、中断、断点、持久化、API边界、四周期交互及版本检查。

发布时同步递增脚本头部、`VERSION`、package和lockfile版本，运行 `npm run build:meta`，测试通过后同版本原子部署两个脚本文件。代码提交GitHub不会自动部署服务器。[部署、备份与回滚说明](deploy/README.md)。
