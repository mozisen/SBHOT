# 烧饼论坛热榜 1.1.0

基于 NodeSeek 热榜插件 1.1 的侧栏交互，为 https://sb.sb/ 重新适配数据和样式。参考根目录的论坛助手了解同源请求和侧栏结构，不包含助手的发帖、回复等功能。

## 安装

安装 Tampermonkey 后，点击 **[安装 / 更新烧饼热榜](https://raw.githubusercontent.com/mozisen/SBHOT/main/shaobing-hot.user.js)**，在 Tampermonkey 中确认安装，再刷新烧饼论坛。面板位于侧栏用户卡片下方。

已有 1.0.0 手动粘贴版的用户，需要通过上述链接更新一次，才能接入 GitHub 更新地址和新增权限。不要同时启用两个副本。

支持 24 小时、30 天、全部三个时间范围；回复热度 / 浏览热度切换；默认展示前 10 条，可展开官方提供的完整榜单（核验时短期榜 20 条、总榜 100 条）。点击标题进入主题，鼠标悬停查看作者、版块和计数。遵循论坛明暗主题。移动端是否显示侧栏沿用论坛自身布局，不添加悬浮遮挡。

## 数据说明

- 数据直接读取官方 `/pages/top/`、`/pages/top/30d/`、`/pages/top/all/`，保持官方顺序。
- 官方提供的周期不是原 NodeSeek 插件的“实时 / 日榜 / 周榜”，因此按真实范围标注，不生成模拟周榜。
- 24 小时、30 天统计对应周期内新增浏览 / 回复；全部统计累计值。来源说明以论坛页面为准。
- 官方页面说明每 15 分钟更新，脚本同周期缓存 15 分钟；页面可见时定时检查，回到标签页时检查过期数据。手动刷新重新读取页面，但不能促使官方提前生成榜单。
- “HH:mm 获取”表示本机获取时间，不冒充服务器生成时间。失败保留该周期旧数据并标注，没有缓存时提示重试。
- 榜单仅访问烧饼同源网页，沿用当前登录状态；版本检查仅访问本仓库的 GitHub Raw 元数据，不携带 Cookie。无需 API Key，不进行账户写操作。无侧栏页面不发起热榜请求。
- updateURL/downloadURL 指向本仓库，避免被 NodeSeek 原版覆盖。

## 每小时版本检查与自动安装

脚本在烧饼页面运行时，首次检查后每小时读取 GitHub 上的版本元数据，跨刷新保存检查时间。浏览器休眠或标签页被挂起时不能准点执行，恢复后补查；关闭全部烧饼页面后，脚本内检查停止。失败不会影响热榜，下一小时重试；油猴菜单“检查烧饼热榜更新”可立即重试。发现新版时显示安装入口，不弹出标签页。

**后台自动安装由 Tampermonkey 管理，与脚本的每小时检测是两个机制。**

1. 打开 Tampermonkey 管理面板 → 设置，必要时将配置模式改为高级。
2. 在“脚本更新 / Userscript Update”中启用检查更新，并启用“自动安装 / Automatic installation”。根据实际版本提供的选项选择检查间隔；若没有 1 小时选项，不能通过本脚本强制设为 1 小时。
3. 打开本脚本的设置，确保“检查更新”已启用，更新 URL 指向本仓库的 `shaobing-hot.meta.js`。

普通用户脚本不能自行覆盖 Tampermonkey 中已安装的源码，也不能修改管理器全局更新间隔。因此本项目实现的是**每小时版本检测 + 管理器原生自动安装支持**，不承诺每小时检测后立即静默安装。Tampermonkey 实际安装时机、权限确认和调度以管理器为准；新版本通常在刷新或重新打开页面后运行。

参考：[Tampermonkey 更新元数据](https://www.tampermonkey.net/documentation.php#meta:updateURL)、[自动安装设置说明](https://www.tampermonkey.net/changelog.php)。

## 发布新版

同步递增脚本头部、`VERSION`、`package.json` 与 lockfile 版本，运行 `npm run build:meta` 生成元数据，然后执行 `npm test`、`npm run check` 和浏览器检查。将 `.user.js` 与 `.meta.js` 在同一提交推送到 `main`。仅修改代码但不增加版本号，不会触发管理器正常升级。

## 开发与验证

Node.js 22 或以上；`npm ci` 安装测试依赖，`npm test` 运行 DOM 行为测试，`npm run check` 检查脚本语法。

`node tests/browser.cjs` 运行 Chromium 渲染验证（首次运行需 `npx playwright install chromium`），截图存放于 `artifacts/`。自动测试使用只读 HTML 样本，不向论坛提交操作。

`tests/fixtures/top.html` 是 2026-11-02 从官方榜单提取的两个热门主题区块，用于结构回归；不将成员排行榜、页面脚本和个人登录数据带入样本。实际联网核验使用当时的公开页面，不能保证未来网站结构永不变化。

开发工作区遵循 Trellis 流程，每次修改更新测试、验证通过后提交。公开仓库只发布安装文件、工具、测试与说明，不包含本地参考助手和会话记录。
